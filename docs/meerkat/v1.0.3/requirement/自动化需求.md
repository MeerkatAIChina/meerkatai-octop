# Octop 原生自动化需求

状态：待评审。日期：2026-10-11。版本目录是本次设计归档编号，不代表已经发布，也不修改当前软件版本。

## 1. 产品定位

在 Octop 的「任务」菜单下面，新增同级菜单「自动化」。用户选择已有专家、填写任务、配置输入输出及运行规则后，平台持续发现工作、调度专家、监控执行、管理重试并整理产出。

业务能力由专家及其 Skill 定义。专利分析只是首个验证场景；平台不能出现专利专用页面、字段、状态或调度分支。以后增加新业务，应通过创建专家、配置 Skill 和新建自动化计划完成。

## 2. 已确定约束

1. 原生集成 Octop，沿用登录、权限、数据库、工作空间、启动停止和发布流程，不增加外置调度服务或第二个 Agent 平台。
2. 复用现有专家管理及 Skill 配置，不建设第二套专家目录，不在自动化页面编辑 Skill。
3. 保护存量功能、数据和配置；新功能停用时不产生调度、目录扫描和后台执行。
4. 支持持续运行、目录新文件检测、运行仪表盘、失败重试、人工重跑和产出打包。
5. 开发任务按角色划分，可由人或开发 Agent 承接；角色不是固定人数，也不是实际人员指派。

## 3. 核心用户故事

| 用户要做的事 | 预期结果 |
| --- | --- |
| 创建计划 | 选择专家，填写任务、触发方式、输入和输出，校验后保存 |
| 往输入目录放文件 | 文件写入稳定后自动入队；同一计划不重复处理相同内容 |
| 看当前运行 | 看计划状态、待处理数量、运行中数量、成功失败数量及最近错误 |
| 看某一次运行 | 看输入快照、专家、尝试次数、执行记录、等待原因及产出 |
| 失败后处理 | 可按规则重试，也可手动重试；原记录及原产出不被覆盖 |
| 再分析已完成文件 | 创建关联原运行的新运行，可明确选择原配置或当前配置 |
| 暂停计划 | 停止发现新工作和启动排队任务；已运行任务按原流程结束 |
| 下载交付物 | 下载单项文件或经过校验的产出包 |

## 4. 首版范围

- 单步计划：一个已有普通专家负责一个任务；可同时创建多个计划。
- 手动、定时、目录新文件三种触发方式；手动上传支持逐文件建立运行。
- 首版目录输入、输出位于所选专家的工作空间，兼容其现有本地或远程存储配置。
- 一个文件对应一个运行；无文件任务支持手动或定时触发。
- 持久化队列、尝试记录、重启核对、取消、超时、等待人工、产出校验和打包。
- 单个 Octop 服务实例运行，不承诺多实例高可用。

首版不包含：多步骤可视化流程编排、跨专家流水线、团队专家嵌套、任意宿主机目录授权、云盘连接器接入、多机执行节点、自动发布到外部渠道、业务分析质量的通用判定。

## 5. 验收方向

两种不同业务 Skill 通过同一套计划、运行和产出流程。既有聊天、任务、专家、工作空间、备份恢复和自定义菜单通过回归。连续运行与故障恢复通过验收后，才能对外说明支持 7×24 持续运行；当前文档和代码调研不等于该能力已经交付。
